# 会话成本计（@local/cost-meter）2.0.0

仓库：<https://github.com/BeckChiang/dsh-cost-meter>（跨机可直接 `git clone` 后 `plugin_manager install_bundle`）。

DeepSeek Harness 的输入框下方挂一个成本读数：**累计成本拆分** + **本轮 / 上一轮成本**，本轮缓存命中成本超线时变色告警（1.3.2 起改为「每步上下文 + 会话累计」双判据）。点开面板能看到每一笔怎么算出来的。

## 读什么

- **累计**：本会话从头到现在的总成本（缓存命中 + 非缓存输入 + 输出）。**按每一步请求发生时的峰谷价分别计价后求和**，所以历史金额一次定稿，不会因为过了 12:00 / 18:00 或刷新页面而改写。
- **本轮 / 上一轮**：从你发出这条消息算起、这一轮对话的累计成本。会话在跑时显示「本轮」，停下后显示「上一轮」。
- **判据有两条线（1.3.2 起）**：① 每步上下文（`cacheRead + 非缓存输入`，取近 3 轮每步中位数）≥ 200k 变黄、≥ 400k 变红——切换会话真正能省下的是它，且与这轮跑了几步无关；② 会话累计成本 ≥ ¥3 变黄、≥ ¥8 变红——钱包的绝对预算。两者任一越线就变色，并说明是哪条触发。旧口径（本轮缓存命中 ¥0.1/¥0.3）只保留给「账本拿不到」的退路。
- 点开面板会写明：为什么是这个颜色、距离下一条线还差多少、当前单价是高峰还是空闲，以及累计是按步计价还是按现价折算。

## 计价口径

早期版本（≤ 1.1.0）用「当前时刻」的峰谷价乘整个会话的累计 token。时钟一跨峰谷分界，历史累计金额就整体翻倍/减半，与真实账单不符。1.2.0 起改为**按 step 计价**：

- Host 半边注册 `GET /api/cost-meter/ledger?id=<sessionId>`（需要 `x-cost-meter: 1` 头），从 `ctx.sessions.get(id).snapshotEvents()` 读原始事件流，交给 `lib/ledger.mjs` 折叠成账本。
- 每个 `assistant/message` 的 `usage` 用它**请求开始**的时间戳（`step/start`，缺失时退回消息时间）和该步所用模型（`request/context` / `request/header` 声明的最近一个）单独计价；`cacheWriteTokens` 不计费（已含在非缓存输入价里）。
- 结果按 `session.seq` 缓存：seq 没变就复用，不会每步重算事件流。
- 会话 id 在宿主存储里带 `session-` 前缀（`SessionHeader.id` 形如 `session-<uuid>`，日志目录名也是它）；路由对「带前缀」和「裸 uuid」两种写法都会试一遍，避免查不到就静默退回按现价折算。
- 账本按 turn 号聚合，所以「本轮」取当前 turn 桶、「上一轮」取最后一个有 `usage` 的 turn 桶，与时钟无关。
- 拿不到账本（宿主未接入、会话不是 live、旧版本）时退回旧的按现价折算，并在面板里明说「暂按当前价折算」。

## 文案语言

面板文案**固定中文**，不跟随界面语言（2026-11-11 按用户要求）：`client.js` 里 `t` 先查 `ZH` 字典，只有缺键时才落到 `ctx.locale.bind('cost-meter')`。这样界面切到英文、或 locale 命名空间没命中而回退成原始 key 时，面板依然是「累计 / 本轮 / 缓存命中」等中文。`EN` 字典与 `en` 注册保留，供将来恢复多语言时直接启用。

## 面板结构

面板（2026-11-14 改版，宽 340px，窄屏自适应）。**每个分区都是「描边框 + 小标题」同一种壳**（`box()` 统一生成），不同分区之间靠边框与间距分隔，不再用分隔线断句：

1. **累计**：小标题 `累计`，框内 18px 金额独占一行——金额是本面板的主角。
2. **DeepSeek 官方价**（计价时段框）：标题右侧给出带上单位的缓存命中单价（`¥0.02/百万 tokens`）；下面圆点 +「当前高峰时段 / 当前空闲时段」；再往下是高峰窗口、空闲规则、距下一次切换的**时长 + 具体时刻**（如「距进入空闲 52 分钟（周三 12:00）」），末行注明「人民币；法定节假日未按高峰计」。周末会直接跳到「（周一 09:00）」。
3. **成本构成**：一条三色堆叠条，整条长度 = 累计总成本（100%），三段按各项成本占比切分——缓存命中（品牌蓝）/ 非缓存输入（琥珀）/ 输出（红）。条下三行图例给出色点、名称、token 量、成本占比、金额。
4. **本轮 / 上一轮**：框内是成本合计、缓存命中，以及状态徽标（`正常`/`注意`/`超限`/`待定`，带同色描边，右侧写距下一条线还差多少，如「距黄线：每步 +175k / 累计 +¥2.9」）与变色原因。
5. **趋势**：四行「标签 + 数值」右对齐——`每步上下文 208.4k`（品牌蓝）、`每轮增长 +4.3k`（增长过 1k 转琥珀，持平为灰）、`再 10 轮成本 ¥4.37`（正文色）、`切会话首 3 轮 ¥0.13`（品牌蓝）。数值 14px/600、等宽数字，标签 11px 三级灰。
6. **判据**：两行判据（会话累计 / 每步上下文）+ 计价口径（按步计价 / 按现价折算）；未收录模型时多一行点名提示。

文案原则：每条提示独立成行、**不超过 24 字**，避免出现只剩两三个字的短换行；层次靠「描边框 + 小标题」、字号/字重/颜色区分，不靠长句堆叠。折叠态的触发按钮加了 `title`，悬停即可看到当前计时段与窗口。

## 价格表

内置官方价（CNY / 百万 tokens），高峰 = 北京时间周一至周五 9:00–12:00、14:00–18:00，空闲价为高峰的一半；法定节假日未单独处理。

| 模型 | 缓存命中 | 非缓存输入 | 输出 |
|---|---|---|---|
| deepseek-flash（空闲 / 高峰） | 0.02 / 0.04 | 1 / 2 | 4 / 8 |
| deepseek-v4-pro（空闲 / 高峰） | 0.15 / 0.30 | 4.5 / 9 | 13.5 / 27 |

价格表在 `lib/ledger.mjs` 顶部 `PRICES`（Host 与客户端共用这一份定价口径）。阈值在 `client.js` 顶部：`WARN_CTX_TOKENS` / `RED_CTX_TOKENS`（每步上下文）、`WARN_SESSION_YUAN` / `RED_SESSION_YUAN`（会话累计）、`RED_CACHE_YUAN` / `WARN_CACHE_YUAN`（仅退路），面板文案里的占位符会自动跟着变；`FRESH_CTX_TOKENS` 是新会话的每步上下文假设值（默认 2 万），只影响「切新会话前 3 轮约 ¥x」的估算。

## 安装

需要一个已启用客户端插件的 DeepSeek Harness Desktop / Web（宿主侧要有 `conversation.composer.dock` 这个槽位，1.1.0 起随官方 `@deepseek-ai/dsh-client-ui-conversation` 提供）。

1. 解压，把 `cost-meter/` 整个目录放到本机任意稳定位置（例如 `<工作区>/plugins/cost-meter`）。不要放在同步盘里运行——工作区之外含重解析点的路径会让命令类工具失效。
2. 安装到 profile：
   - 让 DSH 里的 agent 调用 `plugin_manager`，`action: install_bundle`，`target` 传解压后 `cost-meter/` 的绝对路径；
   - 或者用 CLI（不同版本参数不同，先 `dsh plugin --help` 确认 add / local 的写法）。
3. 装完刷新页面（Ctrl+Shift+R）。底部出现 `¥累计 · 本轮 ¥x` 即生效；没出现就重启一次桌面 app（客户端 bundle 有缓存）。

## 测试

`node test/smoke.mjs`：最小 React 替身直接渲染 dock 组件（30+ 断言），覆盖文案层次、高峰/空闲两态、倒计时方向与具体星期时刻、账本命中/缺席、双判据的黄档与红档、预测行、三色堆叠条宽度与占比、文案长度上限（≤26 字，防止再出现短换行）。无第三方依赖，Node 20+ 可直接跑。

## 卸载

`plugin_manager`：`action: set_plugin`、`target: include:cost-meter`、`enabled: false`；要连安装记录一起清就 `remove_bundle`。

## 已知限制

- **Host 半边要重启 app 才生效**：`index.js` 与 `lib/ledger.mjs` 是宿主代码，只在启动时加载；装完 1.2.0 后重启一次 DSH 桌面 app，面板才会从「累计暂按现价折算，会漂移」变成「累计按每步当时价计，不漂移」。
- 账本只覆盖**本会话自己的** step。fork 出来的子会话会把父会话的事件一起带进来（与 `tokenUsage` 投影口径一致），不另做去重。
- 会话不是 live（例如已归档）时拿不到账本，退回按现价折算。
- **本轮起点只在内存里**（仅退路逻辑用）：前端模块重新求值后 Map 清空，当前这一轮的「本轮」会从重载那一刻起算，面板会写「本轮起点未知」。
- 多会话互不影响：状态按 `sessionId` 分键，切会话再切回来仍接着原会话的起点算。
- 依赖宿主投影 `tokenUsage`（字段 `cacheReadTokens` / `uncachedInputTokens` / `outputTokens`）与 `modelSelection`；宿主改字段名会读不到数。
- 模型不在 `PRICES` 里时按 `deepseek-flash` 计价（`FALLBACK_MODEL`），面板会注明「含未收录模型，按默认价估算」。
- 未计入缓存写入费（`cacheWriteTokens`）：官方按缓存未命中价计，已包含在非缓存输入里。
- 请求跨峰谷分界（11:59:58 发出、12:00:03 返回）时按**请求开始时间**归段，这是可复现的口径，但不保证与账单逐笔一致（账单不公开其取时点）。

## 判据

两条正交指标，任一越线即变色（细节见「读什么」第 3 条）：

| 指标 | 黄线 | 红线 | 怎么取 |
|---|---|---|---|
| 每步上下文 | 200k tokens | 400k tokens | 近 3 轮的 `(cacheRead + 非缓存输入) / 步数` 中位数 |
| 会话累计成本 | ¥3 | ¥8 | 账本 `totals.cost`（按步计价，不会漂移） |

为什么不再只看本轮缓存命中金额：那个数等于 `上下文 × 步数 × 单价`，把步数也乘进去了——同样 90k 上下文的两个会话，一个跑 5 步（¥0.01）一个跑 158 步（¥0.58），后者会被误判成「很重」，而真正该切换的信号是「每一步都要重付多大的上下文」。峰谷价只影响金额折算，不影响上下文重量，所以上下文线用 token、成本线用人民币。

预测口径：`按近 3 轮节奏，再 10 轮约 ¥x` = 近 3 轮每轮成本中位数 × 10；`切新会话每步约 2 万，前 3 轮约 ¥x` = 当前每轮成本 × (2万 / 当前每步上下文) × 3，只在当前每步上下文 > 4 万时给出（否则切换不划算，不显示）。

## 2.0.0 说明
